# P0 自动验收

在项目根目录执行：

```bash
python3 scripts/check-all.py
```

需要 Python 3、Go（支持 `-race`，Linux 下需 C 编译器）、运行中的 Docker，以及本地 `mysql:8.4.10` 镜像。缺少镜像先执行 `docker pull mysql:8.4.10`。无需启动业务服务，无需配置 `.env` 或真实 API Key。预计数分钟，首次编译可能更久。

脚本新建随机名称的 MySQL 容器及临时上传目录，在随机回环端口运行编译后的服务；不读取 `.env`，不操作已有服务、数据库或 `test.mp3`。退出时清理本次容器、匿名卷和上传目录，保留 `/tmp/audio-check-report-*` 日志和测试二进制供排查。正常异常及 Ctrl+C 会清理，脚本自身被 SIGKILL 或机器断电时无法保证清理。

| 覆盖层 | 检查内容 |
| --- | --- |
| 静态与竞态 | `go vet ./...`；全部包 `go test -race -count=1 -v ./...`，数据库真实连接，任何 Skip 视为失败 |
| 上传集成 | 缺少文件、非法扩展名、空文件、文件超限、请求体超限、恰好50MiB、事务插入失败补偿 |
| 查询集成 | 任务/录音详情、分页参数及排序、不存在资源 |
| 并发上限 | 默认3；摘要阶段保持占位、第四条排队，成功/错误/panic释放名额，领取SQL失败后可恢复，取消后收尾 |
| 后台集成 | 竞争领取一次、转写失败、panic、取消、阶段结果与状态事务回滚 |
| 摘要测试 | 正常响应、空数组、非2xx、超时、截断、非法JSON、缺字段、null及错误字段类型；完成状态回滚 |
| 重试集成 | 非法状态/ID、并发重试、旧数据清空、计数增加、事务回滚 |
| 删除集成 | 终态删除、活动状态拒绝、文件缺失、文件删除失败、SQL失败、删除与重试竞争 |
| 真实进程HTTP | 健康检查、404、参数错误、异步上传、Mock转写至摘要替身、列表与结果、文件删除 |
| 生命周期 | 完成结果重启保留、SIGKILL后遗留任务标失败、HTTP手动重试、SIGTERM取消在途任务并退出0 |

正常执行最后显示 `ALL PASS`，退出码为0。任何失败显示 `FAIL`，退出码非0；日志目录在启动时打印，`passed.json` 只记录已通过组，不代表全部通过。进程测试保留生产 Mock 的20%失败率，只对 `transcription_failed` 最多重试9次；连续10次失败仍报失败，其他错误立即失败。

这是一套 P0 回归套件，不是所有可能故障的穷举。真实 ASR 不在当前实现中；真实 DeepSeek 网络、密钥、模型效果及费用未验证，摘要使用本地 HTTP 替身；Dockerfile/Compose 空环境构建与卷重建持久化、机器断电、COMMIT响应丢失、长期负载也不在本脚本范围。数据库事务错误、并发边界和LLM异常由现有可控集成/单元测试覆盖，不靠生产Mock碰运气制造。
